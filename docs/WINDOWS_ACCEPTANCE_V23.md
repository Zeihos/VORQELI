# Windows-приёмка v0.23.0: автозапуск и безопасное обновление

Требуется Windows 10/11 x64, администратор для первичной установки, тестовая машина/VM и возможность восстановить DNS. **На пользовательском ПК ничего ниже не проверено автоматически.** Не выполняйте тесты переключения DNS на критичном компьютере.

## A. Проверка сборки GitHub

1. Восстановить все файлы в корне `Zeihos/VORQELI` (особенно `.github/workflows/windows-build.yml`, `pyproject.toml`, `assets/`, `src/`).
2. Убедиться, что шаг `Verify checkout completeness and release versions` успешен.
3. Подтвердить `Run tests`, `Smoke-test full Windows installation and uninstall` и `Upload Windows application`.
4. Убедиться, что появился `VORQELI-Connect-v0.23.0-Windows`, скачать EXE, Setup и SHA256SUMS.txt; сверить SHA-256.

## B. Единая регистрация автозапуска

1. Запустить установленное приложение от администратора и включить автозапуск в настройках.
2. Проверить `VORQELI-Connect.exe --doctor --doctor-output doctor.json`: `startup_registration` должно быть `task`, а не `conflict`.
3. Убедиться, что в HKCU Run **нет** второго значения `VORQELI Connect`.
4. Выключить автозапуск — статус должен стать `missing`. Если задача не удаляется, приложение должно показать ошибку, не заявляя об успехе.
5. Смоделировать ситуацию старой задачи и запуска приложения без прав администратора: создание второго HKCU Run-значения **не должно происходить**, вместо этого нужно сообщение о необходимости запуска от администратора.

## C. Защита установщика от обновления работающей программы

1. Открыть VORQELI, нажать крестик — окно скрывается в трей, программа остаётся запущенной.
2. Запустить установщик обновления: он должен отказаться от перезаписи работающего EXE и попросить закрыть приложение.
3. Выбрать в трее «Выход из приложения», дождаться остановки собственных модулей и восстановления DNS.
4. Повторно запустить обновление — установка должна пройти, настройки сохраниться.
5. Проверить, что нет одновременно запущенных копий приложения и двух автозапусков.

## D. Обязательное end-to-end испытание

- Запустить DPI / Telegram / GeoHide по отдельности и вместе; проверить, что пользовательские тестовые сайты действительно доступны, а не просто запущены процессы.
- Проверить полное и частичное соединение, потерю сети и возврат; убедиться, что диагностика не раскрывает ключи.
- Включить ON, закрыть в трей, перезагрузить — состояние должно быть восстановлено. Повторить для OFF, убедиться, что модули не запустились.
- Проверить GeoHide при смене Wi-Fi/Ethernet, повреждённом backup и отказе PowerShell. Восстановить DNS вручную, если автоматический возврат не сработал.
- Удаление должно отказать при работающей программе или невосстановленном DNS.

### Интерпретация

`startup_registration: conflict` означает одновременное наличие записи HKCU Run и задачи Планировщика — **требуется ручное исправление**. `unknown` означает, что проверка не завершилась, это не доказательство отсутствия задачи. `connected` внутри приложения не гарантирует фактический обход блокировки — нужно тестировать целевой сервис.
