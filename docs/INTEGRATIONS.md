# Интеграция DPI и Telegram (0.11.0)

## Поддерживаемая платформа

Windows 10/11. В локальных тестах проверялись только формирование команд, управление процессами и валидация; end-to-end Windows проверка находится в плане.

## DPI (экспериментально)

1. Скачайте пакет только с https://github.com/Flowseal/zapret-discord-youtube/releases.
2. Распакуйте архив и выберите папку, внутри которой находятся `bin/winws.exe`, `lists/list-general.txt` и `LICENSE.txt`. Храните пакет вне каталога временных файлов.
3. Откройте **VORQELI → DPI**. Укажите папку, выберите `FAKE` или `MULTISPLIT`.
4. Нажмите **Запустить**. Если WinDivert выдаёт ошибку доступа, проверьте официальную документацию и права; VORQELI сам не повышает права.
5. Проверьте конкретные сервисы, затем нажмите **Остановить**. Посмотрите журнал `%APPDATA%/VorqeliConnect/dpi-engine.log`.

Ниже — концептуально собираемая команда; полный путь подставляется из выбранного пакета:

```text
bin/winws.exe --wf-tcp=80,443 --filter-tcp=80,443 --hostlist=lists/list-general.txt --dpi-desync=fake --dpi-desync-repeats=6
```

В режиме MULTISPLIT последние два параметра заменяются на `--dpi-desync=multisplit --dpi-desync-split-pos=1`.

**Важно:** это простой прямой TCP-профиль. Он не запускает `service.bat`, не использует список всех `general*.bat`, не запускает UDP/QUIC десинхронизацию и не гарантирует работу Discord/YouTube. Выбор стратегии можно менять после остановки. Не запускайте одновременно с другой службой zapret до проверки конфликтов.

## Telegram (консольный прокси)

1. Скачайте **исходники** https://github.com/Flowseal/tg-ws-proxy.
2. Установите Python 3.12 для Windows, проверьте `py --version` в PowerShell.
3. В PowerShell зайдите в распакованную папку tg-ws-proxy и установите его зависимости:

   ```powershell
   cd C:\Path\To\tg-ws-proxy
   py -m pip install -e .
   ```
4. В VORQELI откройте **Telegram**, выберите **эту папку с исходниками**, оставьте поле Python пустым (используется `py` при доступности), при необходимости укажите `python` или полный путь к интерпретатору Python.
5. Установите свободный локальный порт в «Настройки» (по умолчанию 1443) и нажмите **Запустить**.
6. После проверки состояния откройте `tg://proxy` через кнопку, либо настройте Telegram Desktop вручную: MTProto, адрес `127.0.0.1`, выбранный порт, локальный secret из конфигурации VORQELI.
7. При ошибке посмотрите `%APPDATA%/VorqeliConnect/telegram-engine.log`.

Команда запуска, которую строит адаптер:

```text
py -3 -m proxy.tg_ws_proxy --host 127.0.0.1 --port 1443 --secret <32 HEX>
```

Secret создаётся случайно и сохраняется в профиле текущего пользователя. Поскольку он передаётся в аргументах процесса, локальные администраторы могут его прочитать. Приложение не раскрывает secret в журнале событий VORQELI. Не присылайте его в публичные issue.

**Это не установка Flowseal**: VORQELI ожидает, что зависимости внешнего проекта уже установлены, и не пытается менять их автоматически. Текущий адаптер не использует трей-интерфейс `TgWsProxy_windows.exe` и не умеет управлять его настройками.

## Известные ограничения

- Два новых движка запускаются только по кнопке; автозапуск, установка системных служб, полный импорт стратегий и автоматическое обновление пока отсутствуют.
- Статус «Запущен» означает существование дочернего процесса. Проверка «Порт слушает» подтверждает лишь приём локальных TCP-соединений, но **не** доступность Telegram или конкретного сервиса.
- Логи процессов накапливаются в пользовательской папке и их нужно периодически очищать; секретные данные в логах внешнего пакета зависят от версии пакета.
- Python CLI API upstream может меняться: после обновлений Flowseal необходимы новые тесты.

## Новое в 0.11.0

- Кнопка **«Проверить комплект»** проверяет локальные зависимости без запуска движка. Статус OK означает готовность файлов, но не гарантирует успешный обход.
- **«Журнал»** открывает последние 64 КБ непосредственно в приложении и скрывает известный VORQELI Telegram secret. Полные исходные логи могут содержать персональные данные — не публикуйте их без проверки.
- При быстром завершении процесса появляется пояснение с типовой причиной. Файл журнала свыше 2 МБ переименовывается в `.old` при следующем старте. Во время длительного запуска размер лога не ограничивается.
- GitHub Actions использует actions/checkout@v5, setup-python@v6 и upload-artifact@v6 (Node.js 24).
