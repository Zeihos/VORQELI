# GeoHide DNS-over-HTTPS в VORQELI v0.27.0

**Статус: предварительная реализация, требуется тестирование на Windows 11.** Не является
гарантией доступности сервисов, отсутствия утечек DNS либо поддержки конкретной версии Windows.

## Что меняется

В **Настройки → GeoHide · транспорт DNS** выбирается:

- **IPv4 DNS** (по умолчанию): старое поведение, замена адресов системных DNS-серверов у активных физических адаптеров. VORQELI **не** изменяет глобальные настройки Windows DoH. На машине, где DoH настроен другой программой, этот режим не гарантирует именно незашифрованный транспорт.
- **DoH · HTTPS** (явный выбор): перед применением DNS проверяется доступность GeoHide и поддержка команд `Get-DnsClientDohServerAddress`, `Add-DnsClientDohServerAddress`, `Remove-DnsClientDohServerAddress`. VORQELI добавляет в системный каталог Windows **только отсутствующие** записи для фиксированных адресов GeoHide с `AutoUpgrade=True` и `AllowFallbackToUdp=False`. Затем меняет DNS у выбранных адаптеров и перепроверяет результат.

Фиксированный профиль: `https://geohide.ru/dns-query`, IPv4 `159.194.200.33`, `37.230.192.51`. Перед публичным выпуском обязательно сверить данные с актуальной документацией провайдера и проверить реальные HTTPS-запросы. Если сервис меняет адреса или шаблон, выпуск нужно обновить; нет механизма автоматического доверия изменённым настройкам.

**Важно:** Windows 10 / отдельные редакции Windows / корпоративные политики могут не поддерживать системный DoH или запрещать изменения. **Автоматического отката на обычный UDP-DNS при неудачной настройке DoH нет.** При невозможности включения отображается ошибка. Вернуться к IPv4 можно только после отключения/восстановления, вручную изменив режим.

## Безопасность и восстановление

1. До создания глобальных записей Windows приложение записывает журнал намерений `%APPDATA%\VorqeliConnect\doh-restore.json` атомарно (через временный файл, `fsync` и замену).
2. Если соответствующая запись DoH **уже существовала и полностью совпадала**, она не считается созданной VORQELI и никогда не удаляется при штатном отключении.
3. Если запись для GeoHide-IP отличается, операция останавливается **до первого изменения** без перезаписи чужого шаблона.
4. При отключении **сначала восстанавливаются DNS адреса адаптеров** из `dns-restore.json`, а только потом удаляются созданные VORQELI глобальные записи DoH. Если восстановление адаптеров не удалось, системные записи DoH остаются и журнал не удаляется.
5. Если в процессе другая программа изменила DoH-запись, VORQELI не удаляет её и сохраняет журнал для ручного разрешения конфликта.
6. После аварии, даже при отсутствии `dns-restore.json`, отдельный журнал позволяет убрать сохранившиеся глобальные записи DoH через кнопку **«ВОССТАНОВИТЬ DNS»** при выключенном соединении.
7. При незавершённом восстановлении блокируется последующее подключение с другим транспортом DNS. Программу нельзя считать полностью отключённой, пока состояние не восстановлено.

**Ограничение:** глобальные Windows DoH-записи не являются собственностью одного приложения. Журнал уменьшает риск повреждения внешних настроек, но не обеспечивает абсолютной защиты от одновременного изменения другими программами. Фактическое шифрование DNS-пакетов и совместимость с NRPT/VPN/антивирусом нужно отдельно проверять инструментами Windows или сетевым захватом.

## Windows 11: ручной сценарий проверки

Работать в администраторской PowerShell на тестовой машине со снятыми скриншотами **исходных** сетевых настроек.

```powershell
# Перед включением VORQELI: сохранить исходные сведения в безопасном месте
Get-DnsClientServerAddress -AddressFamily IPv4
Get-DnsClientDohServerAddress
```

1. Выбрать DoH, включить только GeoHide (остальные модули можно временно отключить для изоляции проверки), нажать «Подключиться».
2. Проверить, что оба GeoHide IPv4 указаны в `Get-DnsClientServerAddress`. Убедиться, что в `Get-DnsClientDohServerAddress` записи имеют точный HTTPS-шаблон, `AutoUpgrade=True`, `AllowFallbackToUdp=False`.
3. Отдельно проверить **реальные зашифрованные DNS-запросы**, не полагаясь только на наличие записи в каталоге Windows. Если HTTPS-запросы не выполняются, считать режим неподтверждённым.
4. Нажать «Отключиться»; проверить восстановление предыдущих DNS-настроек на всех адаптерах и сохранность **чужих** DoH-записей.
5. Повторить сценарии: второй адаптер отключён, VPN меняет DNS, приложение аварийно закрыто, отказ доступа, потеря интернета, перезагрузка, изменение сети с Ethernet на Wi-Fi.
6. Если `--doctor` возвращает `doh_recovery_pending: true`, не удалять резервные файлы и выполнить штатное восстановление в интерфейсе перед удалением приложения.

**Безопасный CI smoke-тест**: `python scripts/windows_doh_readonly_smoke.py` выводит наличие команды DoH, **не изменяя** сеть или каталог Windows. Это не заменяет ручные испытания на Windows 11.
