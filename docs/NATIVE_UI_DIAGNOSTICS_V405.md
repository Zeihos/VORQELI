# VORQELI Connect v0.40.5 RC — достоверные состояния диагностики

## Исправленные ошибки

Ранее экран использовал строку `app.detail` для определения текущей операции. Она
менялась и при других событиях: сообщениях WinWS, DNS, трея, автозапуска. Поэтому
неоконченная повторная проверка могла выглядеть как старый зелёный `HTTPS OK`.

В `ConnectApp` добавлены два независимых локальных состояния:

- `_diagnostic_scope`: `None`, `all` либо один из пяти сервисов;
- `_diagnostic_fresh`: имена сервисов, для которых в этом процессе получен ответ.

Сканирование переводит выбранные строки в состояние «Проверяется…». Результат
из истории прошлого запуска показывается как «Ранее: …» с приглушённым цветом,
а `HTTP 403`, `HTTP 429` и прочие ошибки не становятся положительной проверкой.
Результаты остальных сервисов не исчезают при одиночной проверке.

Поля обновляются только в уже существующих методах `ConnectApp`, которые запускают
фоновые диагностические потоки и получают сообщения очереди. Рендерер остаётся
только читающим: он никогда не меняет Windows DNS, HOSTS или реестр.

## Проверка перед 1.0.0

1. Запустить полный `pytest` в чистом проекте на Windows.
2. Запустить GitHub Actions Windows build и проверить установочный EXE.
3. Проверить полный и одиночный скан, повторный скан во время сообщений модулей,
   холодный запуск с историей и работу `HTTP 403/429`.
4. Провести реальные тесты сети, трея, DNS/HOSTS и удаления, включая перезагрузку.

Прохождение автоматических GUI-тестов не подтверждает обход блокировок или
готовность стабильного публичного релиза.
