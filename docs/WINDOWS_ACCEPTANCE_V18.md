# Контрольный прогон v0.18.0 на Windows 10/11 x64

**Все пункты ниже требуют реального компьютера Windows.** Тесты в Linux/CI не заменяют проверку WinDivert, Task Scheduler и системного DNS. Перед экспериментами с DNS запишите адреса своих DNS-серверов вручную, чтобы при необходимости восстановить соединение.

## 1. Проверка установки

1. Скачать **только успешный артефакт** Windows build из `https://github.com/Zeihos/VORQELI/actions`.
2. Установить `VORQELI-Connect-Setup.exe` в Program Files обычным установщиком с явным подтверждением UAC. Не копировать EXE и engines в произвольные пользовательские папки.
3. Проверить версию в «О проекте»: `0.18.0`, открыть и закрыть главное окно, убедиться, что трей доступен.
4. Выполнить диагностику без изменений сети:

```powershell
& "$env:ProgramFiles\VORQELI Connect\VORQELI-Connect.exe" --doctor --doctor-output "$env:USERPROFILE\Desktop\vorqeli-doctor.json"
Get-Content "$env:USERPROFILE\Desktop\vorqeli-doctor.json" -Raw | ConvertFrom-Json | Format-List
```

Проверить `schema=1`, `platform=windows`, `startup_registration` после включения автозапуска. Не путать значение `desired_connection` с подтверждённым сетевым подключением: это сохранённое намерение пользователя.

## 2. Проверка трёх компонентов

- [ ] Первый запуск без Python в PATH; интерфейс открывается.
- [ ] Нажать «Подключиться», подтвердить права администратора. Убедиться, что DPI-пакет загрузился только из Flowseal и сверился с SHA-256.
- [ ] Проверить DPI отдельно, Telegram отдельно (порт по умолчанию `127.0.0.1:1443`) и GeoHide отдельно.
- [ ] Совместное подключение трёх компонентов: нет конфликтов, состояние «Подключено» не показывается при падении одного из модулей.
- [ ] Прервать подключение кнопкой «ОТМЕНИТЬ» во время загрузки DPI: после завершения отмены не должно оставаться запущенных собственных процессов.
- [ ] Закрыть окно крестиком, проверить трей, открыть повторно через иконку; повторный запуск ярлыка не создаёт вторую копию.

## 3. Перезагрузка и аварии

- [ ] Оставить «Подключено», перезагрузить компьютер, проверить автозадачу / Run и состояние каждого модуля.
- [ ] Нажать «Отключиться», перезагрузить, проверить `desired_connection=off` в `--doctor`; ни один модуль не должен стартовать автоматически.
- [ ] Прервать питание/аварийно завершить GUI на тестовой машине после активации GeoHide; восстановить DNS из UI.
- [ ] Отключить Wi-Fi после подключения, затем отключить VORQELI. Резервная копия для отсутствующего адаптера обязана остаться; по повторном подключении Wi-Fi восстановить DNS.
- [ ] Сторонний VPN/DNS-клиент меняет DNS во время активного GeoHide: VORQELI обязан не переписать новый DNS, сохранить оригинальный backup и сообщить об оставшихся записях.
- [ ] Смоделировать ошибку записи `%APPDATA%` на отдельном тестовом профиле: команда «Отключиться» должна завершать процессы и сигнализировать о риске восстановления ON после перезагрузки.

## 4. Удаление и обновление

- [ ] Обновить установленную 0.17.0 на 0.18.0, убедиться в сохранении настроек и работе трея.
- [ ] Удалить программу, проверить отсутствие повышенной задачи VORQELI в Task Scheduler и оставшихся процессов WinWS.
- [ ] Проверить, что исходные DNS были восстановлены; если нет, сохранён backup и показана ошибка.
- [ ] Не публиковать стабильный 1.0.0, пока не закрыты критические сценарии.

## Если проверка не пройдена

В сообщении об ошибке нужны: версия Windows, шаг воспроизведения, состояние DPI/TG/DNS, полученный `vorqeli-doctor.json` (перед отправкой проверьте его содержимое вручную), обрезанный обезличенный текст ошибки, отметка о правах администратора. **Не отправляйте секреты Telegram, персональные IP и полный лог без редакции.**
