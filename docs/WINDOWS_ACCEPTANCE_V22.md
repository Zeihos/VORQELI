# VORQELI 0.22.0 — проверка Windows перед релизом

Сценарии с DNS и WinDivert выполняйте на тестовой Windows 10/11 x64 с возможностью восстановить сеть. Убедитесь в доступности локальной учётной записи администратора.

## В автоматическом Windows CI (без изменения DNS)

1. `Verify checkout completeness and release versions` обнаруживает отсутствующие `pyproject.toml`, `.github/workflows/windows-build.yml`, иконку и другие необходимые файлы до установки зависимостей.
2. Установка зависимостей, pinned Flowseal Telegram core и pytest.
3. Сборка `VORQELI-Connect.exe` через PyInstaller, проверка запуска `--version`, `--self-test` и `--doctor`.
4. Установка `VORQELI-Connect-Setup.exe` во временный каталог на CI и проверка файлов.
5. Проверка защиты удаления: когда удерживается именованный mutex приложения, `--uninstall-cleanup` возвращает код 8 и не изменяет систему.
6. Освобождение mutex, обычное удаление и проверка отсутствия установленного EXE.
7. Генерация SHA256SUMS.txt и публикация артефактов.

Результаты этих сценариев требуют **фактического успешного запуска CI** после отправки проекта на GitHub.

## Вручную на Windows (обязательно)

1. Установить приложение в Program Files. Проверить первый запуск и UAC. Не отключать Windows Defender.
2. Подключить все три модуля; сравнить состояние UI с реальной доступностью сервисов, а не только PID.
3. Закрыть окно — убедиться в появлении значка трея и в работе подключения.
4. Перезапустить ПК: при `Включено` приложение запускается и предпринимает переподключение; при `Выключено` не подключается.
5. Вручную изменить DNS в настройках Windows и проверить, что VORQELI не перезаписывает сторонние настройки.
6. Прервать восстановление DNS (например, временно отключить адаптер), проверить сохранение DNS backup и корректный показ ошибки.
7. Попробовать удалить программу с открытым окном: удаление **должно быть отменено**, программа должна остаться установленной.
8. Полностью завершить VORQELI через трей. Повторить удаление: исходный DNS должен быть восстановлен, автозадача удалена и EXE отсутствовать.
9. Проверить сценарий отказа в доступе к Планировщику задач и повторное удаление после разрешения проблемы.
10. Проверить обновление поверх предыдущего релиза, сохранение профилей и отсутствие дублирующихся процессов.

**Ограничения:** проверки безопасности удаления охватывают только текущий сеанс Windows и текущую учётную запись. Несколько сеансов/RDP, обновление работающего EXE и драйвер WinDivert требуют отдельной матрицы испытаний до v1.0.
