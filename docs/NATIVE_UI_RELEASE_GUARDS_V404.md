# VORQELI Connect 0.40.4 RC — обработчики UI и честные статусы

## Исправление P0: первый клик / Tab / фокус

Нативный рендерер в v0.40.1–0.40.3 очищал Canvas и регистрировал
реальные Tk-контролы, но не присваивал `app._logical_size`.
Метод `ConnectApp._focus_control()` использует `self._logical_size`
при любом клике и при навигации с клавиатуры. Из-за этого окно,
созданное обычным `ConnectApp`, могло выдавать `AttributeError` ещё
до выполнения callback, хотя упрощённые тестовые окна обходили вызов.

Исправлено: при каждой отрисовке `Scene` устанавливает размер области
(соответствующий текущему масштабу и scrollbar). Тест воспроизводит
клик через фокус-чувствительный обработчик, а не вызывает callback напрямую.

## Повторная диагностика

Пока выполняется проверка YouTube, предыдущий `HTTPS OK` YouTube
не показывается: вместо него стоит `Проверяется…`.
Остальные сохранённые результаты не объявляются текущей проверкой.
При полном запуске все пять строк временно показывают состояние ожидания.
HTTP 403 / 429 остаётся ограничением, а не «работает».
При другой фоновой задаче кнопки диагностики честно показывают `ЗАНЯТО`.

## Ошибки, ресурсы, стабильность

- Ошибка подключения видна в боковой панели, а ошибка DNS в настройках сети.
- Если Tk не может создать изображение отдельной иконки, доступен fallback.
- Изменяются только нативная UI-отрисовка, автоматические тесты, документация,
  метаданные версий и манифесты. Не изменяются код DPI, Telegram, GeoHide,
  API обновлений, HOSTS, DNS, реестр и настройки пользователя.

## Границы готовности

Модульные/упрощённые Tk-тесты подтверждают логику и компоновку, но не
гарантируют, что Windows 10/11, WinDivert, GeoHide HOSTS или MTProto работают
во всех сетях. Перед публичным 1.0.0: полный pytest, GitHub Actions,
установленный EXE, DPI 100/150/200%, сворачивание/трей, восстановление DNS,
ручное применение и удаление HOSTS, цикл установки и удаления,
подписанный бинарник и реальные сетевые проверки.
