# Проверка автозапуска VORQELI Connect v0.24.0

## Зачем нужна проверка

Повышенная задача Windows имеет право изменять сетевые настройки. Перед её
изменением или удалением VORQELI теперь проверяет описание задачи по XML:
единственный запуск целевого EXE, ожидаемые аргументы, триггер входа
пользователя и уровень HighestAvailable, без дополнительных триггеров. Совпадения имени задачи недостаточно.

## Проверка после установки (Windows)

1. Установите программу в стандартную папку Program Files и разрешите UAC.
2. Запустите программу и откройте настройки автозапуска.
3. Откройте «Планировщик заданий» и найдите `VORQELI Connect`.
4. Убедитесь, что в действии указан именно установленный `VORQELI-Connect.exe`
   с аргументом `--minimized`, а триггер — вход в систему.
5. Выполните `VORQELI-Connect.exe --doctor --doctor-output report.json`.
   `startup_registration` должен быть `task` либо `registry` без прав администратора.
6. Проверьте сценарии с включённым и выключенным подключением после перезагрузки.
7. Проверьте, что удаление посторонней задачи с тем же именем приложением
   не происходит: программа должна сообщить об ошибке, требующей ручного разбора.

`untrusted` — заданная команда/триггер/привилегии не совпадают с ожидаемыми.
`unknown` — Windows не позволила прочитать XML либо произошла ошибка чтения.
Ни в одном случае VORQELI не должен молча удалять или перезаписывать задачу.

### Ограничения

XML-аудит не является криптографической аттестацией исполняемого файла.
Реальная проверка установки, WinDivert, UAC, GeoHide DNS и перезагрузки
по-прежнему обязательна. Никогда не выдавайте эти испытания за пройденные
по одним только результатам Python-тестов.
