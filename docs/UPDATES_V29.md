# VORQELI Connect v0.29.0 — проверка обновлений (предварительная версия)

## Как работает

На странице **«О проекте»** нажмите **«ПРОВЕРИТЬ ОБНОВЛЕНИЯ»**. Только после этого VORQELI обращается к официальному API GitHub Releases: `https://api.github.com/repos/Zeihos/VORQELI/releases/latest`.

Если опубликован новый непробный релиз с единственным файлом `VORQELI-Connect-Setup.exe`, корректным размером и предоставляемой GitHub контрольной суммой `digest: sha256:...`, программа спросит подтверждение на скачивание. Файл скачивается в `%APPDATA%\VorqeliConnect\updates` как `VORQELI-Connect-Setup-vX.Y.Z.exe`.

Скачиваемый файл принимается **только после совпадения количества байтов и SHA-256**, указанного в GitHub Release API. Неполные/подменённые загрузки удаляются, существующий непроверенный файл не перезаписывается. Никакие загруженные исполняемые файлы **не запускаются**. Перед ручным обновлением полностью закройте VORQELI через трей. Установщик запрещает обновлять запущенное приложение.

## Дополнительная защита v0.30.0

API GitHub Releases не допускает HTTP-перенаправления. Загрузка EXE начинаетcя только с точного официального URL и допускает не более трёх перенаправлений на известные GitHub CDN по HTTPS; редиректы на посторонние домены блокируются до скачивания. Уже проверенные файлы публикуются без замены других файлов с тем же именем, а символические ссылки не принимаются. Это не устраняет необходимость **подписи издателя** перед релизом. Ручная проверка подписи: `scripts/windows_release_gate.ps1` (см. `docs/RELEASE_CANDIDATE_GATE_V30.md`).

## Модель доверия и ограничения

- Проверяется официальный URL GitHub и используется TLS, без произвольных доменов и загрузочных ссылок.
- **SHA-256 подтверждает совпадение с информацией GitHub, но не удостоверяет автора/издателя.** Если репозиторий или учётная запись публикации скомпрометированы, один хеш не защитит. Нужна цифровая подпись исполняемых файлов и независимая проверка доверенного издателя или подписанного релизного манифеста с закреплённым публичным ключом.
- Версия **не выполняет автоматическую установку или самостоятельный откат**. Контролируемый откат требует отдельной системы установки предыдущей проверенной версии, проверки DNS и процессов.
- Пока в официальном GitHub нет опубликованного Release, проверка сообщит о невозможности найти релиз. Никакие сторонние EXE не предлагаются.
- Не используются сторонние серверы обновлений, аналитика или фоновый сетевой опрос. Кнопка на странице «О проекте» запускает явный запрос.
- Проверка целостности и загрузка работают в отдельных потоках; нажатие «Подключиться» остаётся независимым.
- Размер API-ответа ограничен 256 KiB, максимальный размер установщика — 250 MiB. Временные `.part` файлы удаляются при ошибках.

## Публикация

1. Восстановите исходники в GitHub. Убедитесь, что Windows Actions успешно выполнили тесты, сборку и smoke-test установки/удаления.
2. Проверьте установщик на реальной Windows 10/11, включая DPI + TG + GeoHide, DNS rollback, перезагрузку и UAC.
3. Подпишите релизный установщик через доверенную цифровую подпись разработчика (в будущей версии приложение сможет проверять её перед запуском).
4. Создайте GitHub Release с тегом `vX.Y.Z` (или `X.Y.Z`, без pre-release) и загрузите в его assets **ровно один** файл с именем `VORQELI-Connect-Setup.exe`.
5. Проверьте, что GitHub Releases API возвращает `assets[].digest` формата `sha256:<64 hex>` для файла. При отсутствии digest текущий клиент правильно **откажется скачивать**.
6. Проверьте на тестовом компьютере вручную, что клиент на старой версии видит новую и загружает файл с совпадающим SHA-256.

## Локальные тесты

`python -m pytest tests/test_update_checker_v29.py -q` проверяет обработку версий, URL, подменённой суммы, сбоя загрузки, повторной проверки и запрета запуска EXE. Сеть в тестах не используется.
