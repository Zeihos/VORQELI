# VORQELI Connect v0.30.0 — Release-candidate security gate

**This is not a stable release.** Python unit tests are not a substitute for Windows installation, elevated DPI, DNS and reboot validation.

## Security improvements in v0.30.0

- The GitHub Releases API **rejects every HTTP redirect**; API metadata cannot be fetched from a substituted website.
- Downloads must start at the exact GitHub release installer URL. Redirects are limited to **three hops** and only known GitHub asset CDN hosts (`release-assets.githubusercontent.com` and `objects.githubusercontent.com`) over HTTPS are allowed. External hosts, HTTP, URL credentials and unexpected ports are forbidden. This check runs **before** following a redirect.
- Asset length and GitHub-provided SHA-256 are both verified. The downloaded executable is never run automatically.
- Publishing a verified file uses an atomic **non-overwriting hard link** rather than `os.replace`. A concurrent download or pre-existing unverified installer cannot be overwritten. Unsupported filesystems fail closed. The update directory must not be a symlink.
- A pre-existing file is reusable only if it is a normal file (not a symbolic link) and its size and SHA-256 match exactly.

**Trust limitation:** A GitHub API digest binds the download to GitHub metadata, **not to the identity of a trusted publisher**. No automatic installation is permitted. This does *not* complete the publisher authentication requirement for v1.0.

## Mandatory signing and checksum gate (manual Windows command)

After issuing a trusted code-signing certificate, signing **both** binaries and generating a fresh `dist/SHA256SUMS.txt` **after signing**, run on Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/windows_release_gate.ps1 `
  -ArtifactsDir dist -TrustedSignerThumbprint "0123456789ABCDEF0123456789ABCDEF01234567"
```

**Replace the example thumbprint with the verified certificate thumbprint**, obtained independently from the trusted publisher certificate. Never use an arbitrary downloaded thumbprint to “make it pass”. The script is read-only and checks SHA-256, a valid Windows Authenticode signature and exact signer certificate thumbprint for both the EXE and Inno Setup installer. An unsigned build is deliberately blocked. Checksums generated by CI *before signing* must be regenerated afterward.

This gate is only one of the release requirements. It cannot verify WinDivert function, network outcomes, DNS encryption, installer cleanup, or successful reboot recovery.

## Required Windows acceptance (P0, not yet performed)

1. Restore all source directories and hidden `.github` folder to the repository root; run a successful Windows GitHub Actions build.
2. Test one-click DPI + Telegram + GeoHide, including a failed module, cancellation and reconnection.
3. Verify actual DNS rollback (DHCP/static, multiple adapters, partial failure, reboot) and DoH traffic behavior, not only PowerShell metadata.
4. Verify elevated Task Scheduler autostart, the explicit saved OFF state, on/off behavior after reboot, tray activation and shutdown.
5. Install, upgrade and uninstall with all modules OFF/ON as appropriate; check complete cleanup.
6. Validate updater against a **real** signed GitHub Release and verify the manual signing gate above. Test recovery from a bad or interrupted update.

**Do not publish v1.0 as ready until all P0 evidence is recorded.**
